# Add new [Format Coconut] leaders

## What this is

Format Coconut is Ravensburger's official singleton multiplayer format. Each
deck is led by a "Coconut" — a digital-only card, not in the physical card
pool, with its own ink identity and a static ability that's active without
being played. The site's Guided Coconut Build models every beta Coconut in
one array, `COCO`, in `flounder-search.template.html`. Nothing here is typed
by hand into `index.html` or `flounder-search.html` — those are generated by
`python3 build_flounder.py`. Only ever edit the template.

Two shapes exist so far:
- **Single-ink** (the original 18): one character, one ink, e.g. `Scar —
  Finally King (Steel)`.
- **Duo** (Beta 2's six): two characters, two inks baked into one card, e.g.
  `Woody & Buzz Lightyear — Best Buddies (Amber/Emerald)`. The reminder text
  ("You can have up to 4 copies of X in your deck") on the card image is the
  tell that it's a real Coconut leader, not new flavor text.

Everything downstream reads a Coconut's ink(s) through `coInks(co)` (~line
4293, right after the `COCO` array, ~line 4238), which returns `[co.i]` or
`[co.i,co.i2]`. **This already exists and is wired everywhere** (ink-cap
legality, deck warnings, the "pick N more inks" wizard, the prebuilt-deck ink
search, both dot displays, the ink-picker option label). Adding a duo leader
today is pure data entry — you do not need to touch any of that plumbing
again unless a THIRD shape shows up (three characters, three inks, or
anything that doesn't fit `i`/`i2`). If you see something that doesn't fit,
stop and say so rather than forcing it into the two-ink model.

## Step 1 — read the screenshots, don't guess

Ben drops the reveal screenshots in a folder (e.g. `newcoconuts/`) — they're
usually stream-capture images, sometimes two cards per image, sometimes
small. Read each one directly. If the ink icons in the color bar under the
title are too small to be sure of the color, crop and upscale rather than
guessing:

```bash
python3 -c "
from PIL import Image
im = Image.open('PATH.webp')
im.crop((x0,y0,x1,y1)).resize((w*4,h*4)).save('/tmp/crop.png')
"
```

Then read `/tmp/crop.png`. Get, per card: full name (`n`), subtitle (`v`),
one or two inks, and the ability text (skip the italic reminder line — it's
boilerplate, not part of `t`).

If a name+subtitle matches an existing *retail* card (common — Ravensburger
often names a Coconut after a real dual-character card), that's fine and
expected: `cocoDeck()`'s `self = CARDS.find(x=>x.n===co.n&&x.v===co.v)`
already finds it, excludes it from the generic pool, and force-includes it
×4. You don't need to do anything about the collision.

## Step 2 — write the COCO entry

Append to the `COCO` array (~line 4238, right before the closing `];` and
the `coInks` line). Match the existing style — short hook, tag-based rec:

```js
{n:"Woody & Buzz Lightyear",v:"Best Buddies",i:"Amber",i2:"Emerald",
 t:"Once during your turn, you may pay 1 ink less for the next Toy character you play this turn. If you do and you have a character named Woody and a character named Buzz Lightyear in play, draw a card.",
 hook:c=>c.sub.includes("Toy"),rec:["cheap","tribal"]},
```

- `i2` only exists on duo leaders. Leave it off entirely for a single-ink one
  — don't set it to `undefined` or `null`, just omit the key (`coInks` checks
  `co.i2` truthiness).
- `hook(c)` is "does this printed card matter for this Coconut" — it scores
  cards in `cocoDeck()`'s prebuilt-deck generator and `pairFor()`'s ink
  ranking. Write it against real card fields: `c.sub` (subtypes array),
  `c.ty` (`"Character"`/`"Item"`/`"Location"`/`"Action"`), `c.c` (cost),
  `c.st`/`c.wi`/`c.lo` (strength/willpower/lore), `c.ef` (plain-English effect
  text, use `(c.ef||"")` before a regex), `c.tx` (rules text, falsy = vanilla),
  `c.kw` (keyword array of `[name, value?]` pairs — e.g.
  `c.kw.some(k=>k[0]==="Evasive")`). Look at a few neighboring `COCO` entries
  for the pattern that matches your card's effect (cost-gated, keyword-gated,
  regex-on-effect-text, tribal subtype).
- `rec` ids are NOT free text — they must be real chip ids from the `GROUPS`
  array (~line 4841, flattened into `AB` at ~line 5029), because
  `cocoDeck()`'s scorer checks `c.ab.has(id)`. Grep `GROUPS=\[` and read the
  `id:` fields rather than inventing a tag name. Reusing a tag your `hook`
  already implies (e.g. `hook` matches "draws a card" AND `rec` includes
  `"draw"`) is the established pattern, not double-counting to avoid.

## Step 3 — write the COCO_PLAN entry

`COCO_PLAN` (~line 7642, a plain object keyed by `co.n`) is what
`builtPanel()` shows under "See fully built decks" — skip it and that view
silently just omits the plan block (no crash), but every existing Coconut has
one, so a new one without it looks unfinished. Same four fields as its
neighbors:

```js
"Woody & Buzz Lightyear":{p:"...3-4 sentences: the engine, why it's built this way...",
  t:["Ink, ...turn 1...","Ink, ...turn 2...","Ink, [Name], then ...turn 3..."],
  g:"...one line: the point of the deck..."},
```

## Step 4 — fix any hardcoded count

Grep for the old count so nothing reads stale:

```bash
grep -n "beta cards\|Coconuts each with a stack" flounder-search.template.html
```

`${COCO.length}` interpolations don't need touching; a few spots (guided-build
intro copy, a code comment) hardcode a number in English.

## Step 5 — build, don't hand-verify in a browser by default

```bash
python3 build_flounder.py
```

Per this repo's `HOW-WE-WORK.md`: no verification theatre. The ink plumbing
is already proven correct (this skill exists because that work was done and
tested once) — a plain data-entry pass through Steps 1–4 doesn't need a
browser round-trip. Only reach for a local server + click-through if you
changed `hook`/`rec` logic you're unsure scores right, or Ben asks to see it.

Don't push to `main` unasked.
