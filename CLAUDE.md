## Step 0 — Sync before anything else (do this every session, no exceptions)

```bash
git fetch origin
git status                    # "behind 'origin/main' by N commits"?
```

If behind:

```bash
git stash -u -m "pre-pull WIP"   # only if status shows untracked local files
git pull origin main
git stash pop                    # if you stashed — safe even if some paths
                                  # say "already exists, no checkout": that
                                  # means the incoming version is identical,
                                  # nothing is lost. Diff before dropping the
                                  # stash if you're unsure.
python3 build_flounder.py        # regenerate BUILD-REPORT.md
cat BUILD-REPORT.md              # card counts, art-tags/rulings coverage
```

line to Ben and keep going, don't stop and rewrite PROJECT.md yourself mid-task

## Hard rules (never break these)

- Only edit `flounder-search.template.html` (the app), `build_flounder.py`,
  `build_rules.py`, or `gen_pages.py`. Never edit `index.html`,
  `flounder-search.html`, or anything under `card/` — all generated, and the
  next build overwrites them completely.
- Never bulk-overwrite or regenerate `art-tags.json`, `card-rules.json`, or
  `rsi-notes.json`. They're hand-authored and irreplaceable — append only.
  `card-rules.json` entries come only from Ravensburger's published set
  release notes / comprehensive rules, never forum posts or your own
  reasoning about how a card probably works.
- Card names must match exactly as `Name - Version` (e.g. `Elsa - Snow Queen`)
  across all three hand-authored files, or they fail silently. Check
  `BUILD-REPORT.md` after every build — it flags any name that stopped
  resolving.
- Ask Ben before making structural changes to `flounder-search.template.html`
  — it's ~10k lines and he has a lot of context on why things are the way
  they are.
- Don't lose user data: decks, collection, dust.
- You are not the only one editing this repo. Kenny's own AI session works
  here too — grep for call sites before renaming or moving anything, and
  prefer small, frequent commits over one large one.

## Build and ship

```bash
python3 build_flounder.py     # offline build, ~1s, reads card-db.json
python3 build_flounder.py --refresh   # also re-pulls card data (~11s)
node smoke.js                 # ship gate — run before every push
```

No other test suite is required day to day; `tests/` (33 suites) exists but
per `HOW-WE-WORK.md` isn't part of the normal loop.
