# Ready Set Ink — partner brief

**Live:** https://readysetink.vercel.app · **Repo:** the one you were just added to

## What it is

A Disney Lorcana card search and deck builder. Unofficial fan content, free
forever, no paywalls — the disclaimer explicitly says we can't charge.

The thing that makes it different from every other Lorcana site is **search by
what a card actually is**. Not just "cost 3 Amber character" — you can type
`blue dog` and get Stitch, or `steel action` and get exactly that, or click one
chip for "cards that punish the whole table". That comes from three hand-built
data files, and those files are where we need help. More on that below.

## How it's put together (the short version)

- **The whole app is ONE HTML file.** `index.html`, ~3 MB, all 2,543 cards baked
  in. It works offline, opened straight off a disk. That's deliberate — don't
  break it by adding a fetch or a framework.
- **You never edit `index.html`.** It's generated. Edit
  `flounder-search.template.html`, then run `python3 build_flounder.py`.
- **The card data is ours.** `card-db.json` in the repo. A normal build reads it
  off disk and never touches the network (~1 second). `--refresh` re-fetches
  from LorcanaJSON + Lorcast.
- **`card/`** is 2,544 static pages, one per card. That's the SEO — generated by
  `gen_pages.py`, don't hand-edit them.
- **Vercel deploys on push.** No build step on their side.

```bash
python3 build_flounder.py     # build (offline, ~1s)
node smoke.js                 # ship gate, ~15s — run before pushing
```

`UPLOAD.md` has the full file-by-file map. `HOW-WE-WORK.md` has the working
style (short version: make the change, ship it, Ben reports bugs — no test
suites, no ceremony).

# What we need from you: tags and rulings

This is the real ask. Everything else is code we can write. These two files are
**the moat** — they can't be scraped from anywhere and they're what makes the
site worth using. Both are badly under-filled.

| File | Filled | Of 2,543 |
|---|---|---|
| `art-tags.json` | **33 cards** | 1.3% |
| `card-rules.json` | **78 cards** | 3.1% |
| `rsi-notes.json` | 4 cards | 0.2% |

## 1. Art tags — `art-tags.json`

What's *in the picture*. This is what makes `blue dog` work. Two fields per card:

```json
"Ariel - Spectacular Singer": {
  "t": ["fullbody", "right", "solo", "outdoors", "water"],
  "a": ["fish", "underwater", "seashell", "mermaid"]
}
```

- **`t`** — structured tags from a fixed vocabulary: framing (`closeup`,
  `fullbody`, `portrait`), facing (`left`, `right`, `forward`), company
  (`solo`, `duo`, `group`), setting (`indoors`, `outdoors`, `water`, `night`),
  pose (`standing`, `sitting`, `action`, `flying`).
- **`a`** — free words. Anything someone might actually type: colours, clothes,
  animals, objects, weather, mood. `"red hair"`, `"blue dress"`, `"holding a
  sword"`, `"snow"`. **This is the important half** — be generous, 5–10 per card.

There's also an `aliases` block (108 entries) mapping a character name to search
words once, so you don't retype "mermaid" on all 16 Ariels.

**A local tagging tool exists** — run the build, then open
`flounder-tagger.html` in a browser. Click through cards, tick tags, hit export,
paste the JSON back into `art-tags.json`. Much faster than editing by hand.

## 2. Rulings — `card-rules.json`

Official Q&A, keyed by card name, from **Ravensburger's published set release
notes only**:

```json
"Woody - Helping a Friend": [
  { "q": "If I play Woody while I have another Toy character in play, can I choose the order?",
    "a": "No, the effects resolve in the order written on the card…",
    "s": "Set 7 release notes" }
]
```

Rules of the road:

- **Official sources only.** Ravensburger set release notes and the comprehensive
  rules. Not forum opinions, not "I think it works like…". If it isn't
  published, it doesn't go in this file.
- Always fill `s` with where it came from. Every ruling on the site is shown
  with its source.
- Quote or closely paraphrase the official answer — don't rewrite it into
  something that might mean something different.
- These become `FAQPage` schema on the card pages, which is how Google shows an
  answer directly. Real SEO value, so accuracy matters more than volume.

## 3. Ben's notes — `rsi-notes.json`

Opinion, not rules. "Watch out", "Ben's take", "Trivia". Ben writes these — they
carry his voice. Leave this one alone unless he asks.

## Ground rules for these three files

1. **Card names must match exactly**, in the form `Name - Version`
   (e.g. `Elsa - Snow Queen`). The build has an integrity check that reports any
   name that no longer resolves — check `BUILD-REPORT.md` after a build; broken
   names fail silently otherwise.
2. **Never bulk-overwrite these files.** They're hand-authored and
   irreplaceable. Add entries, don't regenerate.
3. Run `node smoke.js` before pushing.
4. Ask Ben before changing anything in `flounder-search.template.html` — it's
   ~10k lines and he's got a lot of context on why things are the way they are.

The newest sets and the most-played cards, in that order — a tag on a card
nobody looks at is worth less than a tag on one everybody searches for. The
staples list in the template (`const STAPLES`) is 47 cards people actually play;
that's a good starting target for rulings.
